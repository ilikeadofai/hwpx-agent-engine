## 설계 명확화

- preserve의 첫 텍스트 조각 앞에 개체가 있으면 그 개체는 앞에 남는다. 기존 순서·원문 바이트 보존과 첫 조각 교체 규칙을 동시에 지키기 위한 정정이다. 개체를 문자열 뒤로 이동시키지 않는다.
- 사용자 문서 5종에서 개체가 있지만 텍스트는 비어 있고 기존 hp:t가 있는 문단을 확인했다. 범위 내 첫 빈 hp:t를 재사용한다. 새 hp:t 생성은 빈 문단 삽입에만 허용한다. 텍스트 조각도 빈 hp:t도 없는 개체 전용 문단은 no_text_fragment로 거절한다.
- preserve 끝점은 개체 바로 앞·뒤의 grapheme 경계도 허용한다. textSpans에 들어 있는 텍스트 경계만 허용하면 개체 전용 문단과 개체로 시작·끝나는 문단의 전체 교체라는 §6-2 조건을 만족할 수 없다. textSpans는 기본 reject·삽입 계약으로 유지하며 preserve만 가능한 문단은 modes:["replace"]로 표시한다.
- Rust 기존 단일 문자열 EditOp/VerifyOperation 변형은 유지하고 문단 배열 변형을 추가했다. 외부 명령은 cell.setText 하나이며 두 입력은 상호 배타다. 검증기는 편집기와 모델에 의존하지 않는다.

## 독립 구현과 회귀

hae-verify는 자체 XML scalar 매핑과 원요청의 범위·문단 배열·preserve 플래그로 기대 payload를 계산한다. hae-edit/hae-model 의존성을 추가하지 않았다. Python oracle 역시 엔진을 부르지 않고 원요청과 원본 XML gap을 독립 계산한다. 기존의 보수적 Unicode 부분집합 제한은 유지한다(복잡한 원본 grapheme은 unsupported로 구분하며 추정 분할하지 않는다).

독립 수작업 후보 5종(일반 삽입, 빈 문단 생성, 개체 보존, 개체+빈 hp:t 재사용, 병합 다문단 셀)을 Python과 Rust 검증기가 모두 받아들이고, run 분배·secPr 순서·개체 삭제/내용·탭 종류·병합 속성·문단 텍스트를 변조한 14후보는 둘 다 거절한다. 기존 30개 변이 시험도 유지한다.

실제 문서에서 발견한 셀 안 글상자 문단은 셀 본문의 paragraphs 배열에 포함하지 않는다. 셀 직속 subList/p만 세며, 글상자 등 개체 내부는 보존한다. 이 사례를 합성하여 RED→GREEN 회귀를 추가했다. 삽입 경계의 오른쪽 grapheme이 지원하지 않는 표기이고 왼쪽이 광고 구간이면 왼쪽 원문 위치를 쓴다. 리터럴 탭·CDATA·주석 경계를 포함한 광고 삽입 위치 회귀를 추가했다.

레지스트리 command descriptor에 schemaVersion:"0.2.0"을 추가하고 엔진 workspace 버전을 0.2.0으로 올렸다. 기존 요청 봉투와 프로젝트 파일의 schemaVersion=1은 파일 형식 변경이 아니므로 유지했다. cell.setText 입력 스키마는 text/paragraphs oneOf와 엄격한 controls enum을 제공한다.


## 사용자 문서 속성 시험과 단계 4 재시도

로컬 입력 5종, 실제 executor 편집과 독립 저장 검증 후 Undo/내보내기로 원본 ZIP 바이트 동일성을 확인했다. 개체 포함 문단 30개 preserve 전체 교체, 빈 문단 58개 삽입, 다문단 셀 10개(병합 셀 2개 포함) 교체로 서로 다른 편집 **98건 / Undo 정확 복원 98건**이 통과했다. 사용자 원본·본문·추출 로그를 커밋하지 않는다. 입력 디렉터리 부재 시 시험은 SKIP으로 명시한다.

`spikes/work/stage4-e2e/runs/*.responses.redacted.json`과 대응 script를 프로그램으로 읽어 이전 실패 25건을 대조했다. 수식 노드 지목 1건은 여전히 거절됨을 확인하고 제외했다. 나머지 **24건 성공 / Undo 정확 복원 24건**이다. 셀은 원요청 text를 기존 문단 수의 paragraphs로 전환하고 controls:preserve를 썼다. 24건 중 5건은 개체만 선택한 옛 probe 범위에 편집할 텍스트 조각이 없어 문단 전체 preserve 교체로 범위를 확장해 재시도했다. 따라서 이 5건을 “원래 범위 그대로 성공”으로 해석해서는 안 된다. 구조 생성 범위는 확대하지 않았다.

재실행: `cargo test -p hae-exec --test editable_documents -- --nocapture`. 세 시험은 기존 광고/dryRun 정합성, 새 실제 편집/Undo 속성, 단계4 재시도다. 출력은 수치만 남기며 원문은 로컬에서만 처리한다.
