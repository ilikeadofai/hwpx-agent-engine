## 설계 명확화

- preserve의 첫 텍스트 조각 앞에 개체가 있으면 그 개체는 앞에 남는다. 기존 순서·원문 바이트 보존과 첫 조각 교체 규칙을 동시에 지키기 위한 정정이다. 개체를 문자열 뒤로 이동시키지 않는다.
- 사용자 문서 5종에서 개체가 있지만 텍스트는 비어 있고 기존 hp:t가 있는 문단을 확인했다. 범위 내 첫 빈 hp:t를 재사용한다. 새 hp:t 생성은 빈 문단 삽입에만 허용한다. 텍스트 조각도 빈 hp:t도 없는 개체 전용 문단은 no_text_fragment로 거절한다.
- preserve 끝점은 개체 바로 앞·뒤의 grapheme 경계도 허용한다. textSpans에 들어 있는 텍스트 경계만 허용하면 개체 전용 문단과 개체로 시작·끝나는 문단의 전체 교체라는 §6-2 조건을 만족할 수 없다. textSpans는 기본 reject·삽입 계약으로 유지하며 preserve만 가능한 문단은 modes:["replace"]로 표시한다.
- Rust 기존 단일 문자열 EditOp/VerifyOperation 변형은 유지하고 문단 배열 변형을 추가했다. 외부 명령은 cell.setText 하나이며 두 입력은 상호 배타다. 검증기는 편집기와 모델에 의존하지 않는다.

## 독립 구현과 회귀

hae-verify는 자체 XML scalar 매핑과 원요청의 범위·문단 배열·preserve 플래그로 기대 payload를 계산한다. hae-edit/hae-model 의존성을 추가하지 않았다. Python oracle 역시 엔진을 부르지 않고 원요청과 원본 XML gap을 독립 계산한다. 기존의 보수적 Unicode 부분집합 제한은 유지한다(복잡한 원본 grapheme은 unsupported로 구분하며 추정 분할하지 않는다).

독립 수작업 후보 5종(일반 삽입, 빈 문단 생성, 개체 보존, 개체+빈 hp:t 재사용, 병합 다문단 셀)을 Python과 Rust 검증기가 모두 받아들이고, run 분배·secPr 순서·개체 삭제/내용·탭 종류·병합 속성·문단 텍스트를 변조한 14후보는 둘 다 거절한다. 기존 30개 변이 시험도 유지한다.

실제 문서에서 발견한 셀 안 글상자 문단은 셀 본문의 paragraphs 배열에 포함하지 않는다. 셀 직속 subList/p만 세며, 글상자 등 개체 내부는 보존한다. 이 사례를 합성하여 RED→GREEN 회귀를 추가했다. 삽입 경계의 오른쪽 grapheme이 지원하지 않는 표기이고 왼쪽이 광고 구간이면 왼쪽 원문 위치를 쓴다. 리터럴 탭·CDATA·주석 경계를 포함한 광고 삽입 위치 회귀를 추가했다.

레지스트리 command descriptor에 schemaVersion:"0.2.0"을 추가하고 엔진 workspace 버전을 0.2.0으로 올렸다. 기존 요청 봉투와 프로젝트 파일의 schemaVersion=1은 파일 형식 변경이 아니므로 유지했다. cell.setText 입력 스키마는 text/paragraphs oneOf와 엄격한 controls enum을 제공한다.

## 독립 재검토와 기존 fixture 갱신

Luna가 fcd95c4 기준 소스·합성 fixture를 검토하고 Rust oracle_mutations 2/2(기존 30변이 및 0.2 양성 5/변이 14 포함), Python oracle 90/90과 diff whitespace 검사를 독립 재실행했다. 구체적 반례 결함은 보고하지 않았다. 사용자 입력과 SDK 경로는 열지 않았다. 검토 범위는 이 스냅샷이며, 이후 아래 fixture/거절 reason·시험 집계 정리는 부모의 최종 게이트로 검증한다.

첫 전체 게이트는 과거 editing fixture의 병합 셀 거절 기대값 때문에 실패했다. `editing_expected.json`과 생성기의 병합 셀 기대를 성공으로 고치고 다문단 배열 성공 사례를 추가했다. fixture HWPX 원본은 바꾸지 않았다. 다문단 셀의 text 거절에는 기존 reason:cell_paragraph_count를 유지하면서 새 paragraphs 안내를 제공한다. 광고 속성 시험도 글상자 문단을 셀의 paragraphs 수에 포함하지 않도록 직접 parent를 필터한다.

최종 게이트 로그는 로컬 `spikes/work/v02-stage1/{check-complete.log,oracle-head.log,editable-final.log,mcp-head/summary.json}`에 남긴다. 완료 수치는 이 로그의 fresh 결과만 보고한다.


마지막 계약 회귀 3건을 추가했다. cell.setText는 문단 내부에서 text.replace를 사용해도 응답 Intent를 cell.setText 한 개로 유지하며 다문단이면 expectedParagraphs 배열을 제공한다. preserve의 첫 빈 hp:t에 해석 불가 속성이 있으면 뒤의 요소로 건너뛰지 않고 거절하며 available도 false다. childParagraphsEditable은 textSpans뿐 아니라 preserve만 가능한 자손 문단의 실제 text.replace 경로도 반영한다. 각 회귀를 구현 전 실패로 재현하고 수정 후 executor 저장 관문 통과를 확인했다.

## 총괄 추가 지시 §7-1 반영 (이전 수치 정정)

추가 지시에 따라 preserve 범위에 hp:fieldBegin/fieldEnd가 직접 또는 ctrl 안에 있으면 하이퍼링크 종류와 무관하게 field_boundary_in_range로 거절한다. 개체 전용 문단의 개체 경계는 같은 기존 run의 유효한 위치에 hp:t만 생성할 수 있을 때 길이 0 textSpans로 광고한다. hp:t 내부의 두 개체 사이처럼 새 hp:t를 같은 run의 그 위치에 둘 수 없으면 광고하지 않는다. 새 run은 만들지 않는다.

개체 앞 hp:t가 생기면 뒤 개체의 XML child 인덱스만 바뀐다. rebuild는 hp:t를 제외한 기존 요소의 순서·조상 경로와 nodeId를 보존하며, 저장용 map은 변경된 실제 XML 경로를 기록한다. 캐시 anchor는 nodeId로 추적한다. 독립 검증기는 별도 경로 계산으로 같은 기존 개체를 찾는다. 양쪽 배치 순서(셀 변경→그 표 앞 삽입, 삽입→셀 변경), 프로젝트 저장/재열기, Undo 원본 복원을 시험했다.

**이전 “24건 성공” 집계는 정확한 원 요청 재시도 집계로 사용하지 않는다.** 범위를 확장한 5건을 포함했던 과거 값이다. §7-1 적용 뒤 원래 target·range·text를 유지하고 명시 preserve/기존 문단 배열 인자만 전환한 재시험은 25건 중 수식 지목 1건 제외, **18건 성공·Undo 18건, 6건 거절**이다. 이 6건은 문단 전체 범위로 바꾸지 않고 거절로 남긴다. 기본 fields 안전 거절은 §6의 개체 포함 전수 성공 조건보다 우선하며, 해당 거절을 별도 수치로 기록한다. 성공률이나 이론상 24/25 달성으로 승격하지 않는다.
