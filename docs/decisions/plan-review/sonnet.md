# 구현 계획 일관성 검토 (Sonnet 5.5)

검토일: 2026-10-16. 대상: docs/superpowers/plans/2026-10-16-hwpx-engine-0.1-plan.md(이하 계획). 기준: 설계서(이하 설계서 §), stage0-results.md, model-roles.md. 범위는 일관성에 한정하며 빠진 위험 발굴은 GPT 6.1 Sol 검토 몫이다. 설계서·단계 0 결과·계획과 일치하는 항목(§11 캐시 규칙 본문, 의존성 판 번호 quick-xml 0.39.2·flate2 1.1.9·crc32fast 1.5.0, 이력 상한 100, 요청 순서 책임 분담, S1 사례 수 18+3, 외부 공급자에 보낼 자료 제한 등)은 적지 않는다.

추가로 설계서에는 있으나 어느 작업에도 없는 항목:

- 레지스트리와 명령 노출(설계서 §6): 명령 타입 단일 출처, JSON Schema 생성, command.list/describe, 정의되지 않은 속성 거절, 명령별 조회/변경·지원 능력·이력 정책 선언. 계획은 hae-exec 설명과 schemars 의존성에만 등장하고 작업이 없다.
- document.open/inspect/close, element.query/get 명령의 연결: 1-5는 뷰만, 1-11은 봉투·이력만 다룬다.
- in-process 클라이언트 계약 시험(설계서 §3, §14 단계 1): 1-13은 CLI만 다룬다.
- 입출력 루트를 모든 인터페이스에 같게 적용(설계서 §11): 1-12가 내보내기 경로 거절과 링크 비추종만 말하고, 입출력 루트 정책은 어느 작업에도 없다. 교체용 이미지 파일의 덮어쓰기 금지·루트 검사는 1-10 소관인지도 불명.
- 클린룸 기록(설계서 §12): 인계 기록(명세 ID·작성 역할·검토 역할·근거 유형·첨부 hash), 재사용 이력(핵심 계층으로 가져온 코드), rhwp 재사용의 의존 코드 표시(버전·라이선스·수정). 1-14가 시험 자료 출처만 다룬다.
- 시험 문서 첫째 출처인 사용자의 Windows 한컴 작성 최소 문서(설계서 §13에서 "가장 중요"): 1-14는 rhwp 공개 서식과 합성 문서만 적었다. 단계 4에서만 쓰는 것으로 읽히므로, 단계 1 시험용으로 받을 시점과 manifest 표시(관찰 시험 자료)를 정해야 한다.
- 표시 "0.1 완료" 조건(설계서 §13: 실제 rhwp 프리뷰와 격리 검증 전에는 0.1 완료 표시 금지)과 어댑터 실패 시 기록 문구: 계획에 단계 1 결과 문서(1-16)만 있고 최종 완료 판정 작업이 없다.

## 요약

- 높음 2건: C1(hae-project와 hae-exec 의존 방향이 document.open/project.save 구조와 충돌), C2(진단 코드 crate 위치 때문에 하위 crate가 코드를 쓸 수 없음).
- 설계서 §13 행 중 단계 1에서 명시적으로 대응이 없는 것: 무편집 저장, 해석 불가 요소. 단계 2·3 행(인터페이스·프리뷰·장애)은 개요만 있고 완료 조건이 없다.
- 설계서 항목 중 작업이 없는 것: 레지스트리·스키마 생성·command.list/describe, document.open/inspect/close 등 조회 명령 연결, in-process API, 입출력 루트 정책, 클린룸 기록, 한컴 작성 최소 문서 확보.
- §11 캐시 규칙은 본문(수정 최상위 문단부터 구역 끝까지)은 일치하나 A5–A7의 세부(PrvText, 낡은 표시, 깊은 캐시, 호출 대상 명령)가 빠져 있다.
