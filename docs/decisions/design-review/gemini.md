1. **6~15절 전면 일본어 표기 (언어 혼용 교정)**
   6절 본문("変更命令には...")부터 15절 끝까지 본문 전체가 일본어로 작성되어 있습니다. 설계서 전체의 언어를 한국어 기술 문서 표현으로 통일해야 합니다.

2. **'漢字処理(한자 처리)' 오기 (치명적 용어 왜곡 교정)**
   12·13절의 'Windowsの漢字処理', '漢字処理互換', '漢字処理エンジン'은 아래아한글의 '한글 처리/조판'이 잘못 번역된 표현입니다. 문맥에 맞게 **'한글 조판'** 또는 **'한글 텍스트 처리'**로 수정해야 합니다.

3. **'再開封(재개봉)' -> '다시 열기(재열기)' (일본식 한자어 교정)**
   13절 검증 표의 '再開封'은 영화 재상영 등에 쓰이는 부자연스러운 직역 표현입니다. 5절의 표기와 일관되게 **'다시 열기'** 또는 **'재열기'**로 수정해야 합니다.

4. **'독립 한글 문서 엔진' -> '독립 아래아한글(HWPX) 문서 엔진' (문서명 중의성 해소)**
   제목과 1절의 '한글 문서 엔진'은 한국어(Hangul) 자연어 텍스트 처리 라이브러리인지 HWPX 포맷 처리기인지 모호합니다. 대상 포맷을 드러내도록 **'독립 아래아한글(HWPX) 문서 엔진'**으로 명시해야 합니다.

5. **'판본' -> '커밋' / '리비전' (용어 정확성)**
   2절과 9절에서 Git 커밋 해시(1a76570...)나 특정 개발 버전을 고서·출판물 용어인 '판본(版本)'으로 지칭하고 있습니다. Git 기반 환경에 맞게 **'대상 커밋'** 또는 **'지정 버전'**으로 수정해야 합니다.

6. **1차 범위 서술 모순 교정: '구조 추가·삭제 배제' vs '신규 그림 자원 생성'**
   5절의 "0.1은 구조 추가·삭제를 제공하지 않으므로 지원 편집과 Undo/Redo에서 같은 요소 ID를 유지한다"는 2절의 "교체 자원을 새로 만들고 대상 그림의 참조만 바꾼다"와 충돌합니다. 본문 트리와 패키지 자원을 명확히 분리하여 **"0.1은 본문 구조 노드(문단·표·셀 등)의 추가·삭제를 제공하지 않으므로"**로 수정해야 합니다.

7. **'자원(資源)' 용어 분리 (다의어 혼선 해소)**
   문서 내 임베디드 이미지 파일을 뜻하는 자원(2, 4절)과 메모리·파일 크기 제한 등 시스템 한도를 뜻하는 자원(11절, RESOURCE_LIMIT)이 구별 없이 혼용되었습니다. 전자는 **'미디어 리소스(또는 첨부 자산)'**, 후자는 **'시스템 리소스(또는 자원 한도)'**로 분리 기술해야 합니다.

8. **'原子置換' / '원자 교체' -> '원자적 치환(atomic replace)' (표준 전산 용어 교정)**
   5절("원자 교체") 및 11절("原子置換")의 직역 투 표현을 표준 소프트웨어 공학 용어인 **'원자적 치환'** 또는 **'원자적 교체(atomic replace)'**로 통일해야 합니다.
