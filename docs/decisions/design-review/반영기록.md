# 설계 검토 반영 기록

확인일: 2026-10-16. 검토 대상은 검토전_설계서.md이며 hash는 검토대상.json에 있다. Sonnet·Opus·Gemini의 원래 의견은 각 md, 실제 응답 모델명과 종료 상태는 각 json에 보관한다. 아래 처분은 총괄이 설계서에 반영하고 자체 재검토한 결과다. 수정본에 대한 세 모델의 재승인이나 구현 시험을 의미하지 않는다.

| 검토 항목 | 반영 또는 판단 |
|---|---|
| 언어 혼입·한컴/한자 용어 혼동 | 규범 문서를 전부 한국어로 교정하고 한컴 조판·HWPX 용어로 통일했다. |
| 단일 정규 상태 | 현재 원본 보존 패키지 + nodeId 대응표를 정규 상태로 고정하고 파생물 불일치는 commit 거절로 했다. |
| 본문 ID와 리소스 ID | 본문 노드와 스타일·미디어 공간을 분리하고 Undo/Redo의 동일 실체 복원 규칙을 명시했다. |
| 1회 CLI의 세션 이력 | 한 프로세스 전체 스크립트 모드로 이력을 지원하고 독립 호출 간 이력은 SESSION_REQUIRED로 거절한다. |
| batch 좌표 | 각 단계가 직전 임시 상태를 기준으로 해석하는 순차 의미를 선택했다. Opus의 시작 상태/역순 적용 제안은 대안이며 채택하지 않았다. 단계별 요청 번호·버전은 금지했다. |
| revision·noop | 내용 revision 단조 증가, 오래된 버전 우선 거절, 빈 이력 오류, noop의 Redo 보존을 명시했다. |
| 1,024 요청 상한 문제 | 해당 설계를 제거했다. writer별 순서 번호와 마지막 응답 캐시, 오래된 재송신 거절을 사용한다. 처리된 오류도 번호를 소비해 재시도 의미를 고정했다. |
| 저장·동시 접근 | 프로젝트 경로별 안정된 .lock, 마지막 파일 hash 검사, fsync와 원자적 교체, savedVersion 응답을 명시했다. |
| hash와 ID 대응 | payload 집합 hash와 실제 HWPX bytes hash를 분리하고 구조 경로 대응표를 commit마다 갱신한다. |
| 이력·메모리 | 100개 정상 퇴거는 응답에 표시한다. 메모리 부족은 추가 퇴거로 숨기지 않고 명령을 거절한다. 명시 해제 API를 추가했다. |
| XML·텍스트 보존 | UTF-8 토큰 범위 보존, 제어/불명 속성 경계 거절, 원문 정규화 금지, 최초 run 서식과 FORMAT_COLLAPSED, 빈 run 유지, 캐시 무효화를 구체화했다. Unicode 라이브러리와 XML 파서의 선택은 다음 구현 계획에서 고정할 작업이다. |
| 그림 교체 | 입력을 한 번 읽어 고정하며 정적 파일 검증·원본 bytes 보관·Redo시 재읽기 금지를 명시했다. |
| 렌더러와 ID 매핑 | 구조 경로가 유일하지 않으면 페이지 정보 unavailable. rendered 상태와 한컴 동일 조판을 분리하고 coverage unknown을 허용했다. |
| rhwp 실패·샌드박스 | 최소 지원 문서 프리뷰와 격리 검증을 0.1 완료 조건으로 명시했다. 어댑터 실패 시 코어만 부분 완료다. bwrap 실행 파일이 로컬에 존재하지만 실제 격리 실행은 아직 시험하지 않았다. |
| 공개 코드와 클린룸 | 공개 OSS 열람 자체를 오염으로 보자는 제안은 채택하지 않았다. 라이선스에 따른 재사용과 비공개 한컴 구현의 독립 작성은 출처를 나누어 기록한다. 모델 학습 노출 통제까지 주장하지 않는다. |

현재 폴더는 Git 저장소가 아니다. 제품 저장소를 아직 만들지 않았으므로 설계 커밋은 생성하지 않았으며, 설계 파일의 SHA-256으로 검토본을 식별한다. 코드·의존성 설치·한컴 SDK 분석·Windows 실행은 이번 설계 작업에서 수행하지 않았다.

## 2차 재검토 (2026-10-16)

검토 대상은 검토/개정전_설계서_v2.md(SHA-256 6f6a5ada…a29)다. Opus 5.5가 전체를 다시 읽고 고친 뒤, Sonnet 5.5가 개정본의 내부 모순만 확인했다(sonnet_2차.md·json).

| 항목 | 이전 상태 | 개정 |
|---|---|---|
| 위험 순서 | 원문 보존 XML 편집과 줄 배치 캐시 제거의 실현 가능성을 확인하기 전에 코어 전체를 구현 | §14에 단계 0(S1 XML 보존, S2 rhwp, S3 격리, S4 한컴 재열기)과 실패 시 대응, 단계별 완료 기준 추가 |
| 에이전트의 요청 순서 관리 | MCP 에이전트도 requestSequence를 직접 관리 | MCP·CLI·GUI 어댑터가 순서 번호를 붙이고, 에이전트는 expectedVersion으로 중복 적용을 막음 |
| 적용 전 미리보기 | 없음 | dryRun 추가. 상태·revision·이력·순서 번호 불변, 실제 적용은 같은 expectedVersion으로 재요청 |
| MCP 노출 방식 | 미정 | 명령별 MCP 도구 노출. 명령이 늘면 목록 조회와 범용 실행 방식 추가 가능 |
| HWPX에서 프로젝트로 전환 | 경로·시점 미정 | document.open이 HWPX·.hwpwork를 받고, 첫 project.save가 새 프로젝트를 만들며 이때 잠금. .hwpwork는 열 때 잠금 |
| 조회 계약 | inspect·query 출력과 셀 주소 방식 미정 | 개요 항목, 질의 조건, (표, 행, 열) 주소, 병합 셀 보고, 모호한 결과 처리 명시 |
| 빈 셀 쓰기 | 빈 범위 삽입을 금지하면서 빈 셀 쓰기를 허용 | 빈 셀은 기존 첫 run에 쓰고, run이 없으면 거절 |
| 문단 모양 규칙 위치 | text.replace 문단에 섞임 | paragraph.format 규칙으로 분리하고 같은 값 재사용 명시 |
| 응답 필드 중복 | outcome과 mutated 병존 | outcome 하나로 통일 |
| 스냅샷 메모리 | 공유 방식 미명시 | 패키지 항목 단위 구조 공유 |
| ZIP 재작성 | 해제 내용만 유지 | 바뀌지 않은 항목은 압축 데이터 그대로 복사 |
| 썸네일 | 참조와 함께 무효화(manifest 변경 가능성) | 그대로 두고 낡은 상태로 진단 |
| 시험 문서 출처 | 공개 문서·자작 문서 | 사용자의 한컴 작성 문서, 이용 조건을 확인한 rhwp 샘플, 합성 문서로 구체화 |
| 저장소 위치 | 학교 연구 폴더 | 독립 Git 저장소 후보 지정, 구현 계획 단계에서 생성 |
| 용어 | 차분·중대도·보전·퇴거·판본 | 변경 비교·심각도·보존·해제·버전으로 정리 |

Sonnet 2차 확인에서 나온 여섯 가지(암호화 문서의 열기 처리, clear 이후 오류 코드, 빈 셀 조건, writerId 발급 주체, 기존 프로젝트 잠금 시점, 자소 경계에 걸친 검색 결과)는 모두 받아들여 반영했다. 수정 후 내부 모순 확인은 총괄 자체 점검이며 모델 재확인은 하지 않았다. 구현·빌드·실행 시험은 여전히 하지 않았다.
