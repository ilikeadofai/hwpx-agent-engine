## 1. 항목별 판정

- **표 축 불일치 P1:** 검토와 같은 공개 dimensions.hwpx의 첫 표에서 sz.height 4800→4801 뒤
  setColumnWidths(widths=[20000,22000]), sz.width 42000→42001 뒤 setRowHeights를 각각 실행했다.
  두 경우는 ed03b01 이후 executor+독립 검증 경로에서 성공한다. 테스트 이름은
  `review_p1_opposite_axis_and_remaining_source_contradictions`다.
- **남은 광고 불일치:** 요청하는 축 자체의 cellSz 모순 또는 폭 총합 모순은 planner가 거절하지만
  capability가 true를 내보내던 경우가 남아 있었다. `8bb647e`는 모델 query에서 격자·축의 기존
  치수 관계를 검사하여 false/table_geometry_unsupported를 반환하게 한다. 편집기/검증기의
  축별 허용 규칙을 약화하지 않았다.
- **표 명령 전체:** `advertised_table_commands_execute_with_basic_arguments`는 공개 합성
  dimensions/layout_height 각각의 단순 표에 대해 표 편집 6개와 cell.setSize·setFormat·setText의
  광고→기본 요청 dryRun→실제 실행을 검사한다(9명령×2 fixture). 병합·경계·요청값별 미지원은
  별도 기존 시험과 설계서의 현재 한계로 유지한다. 모든 표본·모든 인자의 전수 성공은 주장하지 않는다.
- **PrvText:** `b19cf26`에서 equation.setScript의 디코딩된 old script가 UTF-8 PrvText에 유일하면
  교체하고, 부재·중복·빈 값이면 보존+stale로 확정했다. setProperties는 script를 바꾸지 않는다.
  엔진·hae-verify·Python oracle이 각각 기대값을 계산한다. header.setText·field.setText·form.fill의
  문단 단위 치환, cell.setFormat 등 텍스트 불변 명령의 유지, 비UTF-8·누락 preview 규칙도 설계에 적었다.
- **Redo 공백:** 수식 속성과 form.fill의 정확한 편집 후 archive 복원 assertion을 추가했다.
- **렌더러 격리:** `9baa43d`·`8c2fcd4`는 실제 renderer가 필요한 executor preview 4건과 adapter 9건을
  명시적 ignored로 두고 check.sh가 executable renderer를 찾으면 총 13건을 별도로 실행한다.
  없으면 시작·끝에 SKIP를 출력한다.
  렌더러 경로를 지정했는데 실행 중 실패하는 경우는 계속 실패다. 기존 sandbox/오류 시험은 유지한다.
- **설계서:** `docs/superpowers/specs/2026-10-18-hwpx-engine-0.3-design.md`에
  57개 명령(신규 34개)·ID·캐시·PrvText·history·자원·독립성·광고·현재 한계를 확정했다.
  레지스트리 이름과 표 행을 비교하여 57/57, 누락 0·추가 0을 확인했다.
  실제 CLI command.list도 57개·중복 0이었다(`command-list.json`).
- 검토의 임시 로그 추적은 시작 HEAD 2728d27에서 이미 제거되어 있었다(`git ls-files .tmp` 결과 없음).

## 2. 재현과 근거 경로
