### 8.2 명령별 최종 규칙과 독립 검증

- `table.setColumnWidths`: 가로 셀 구간·표 전체 너비만 복원/검증한다.
  바뀌는 셀 너비는 좌우 유효 여백보다 커야 한다.
  모든 `cellSz.height`, `sz.height`, 상하 여백과 상대 높이 기준은 원문 그대로 보존한다.
- `table.setRowHeights`: 행은 셀 높이 구간만으로 복원한다.
  배치 높이는 구간 제약으로 쓰지 않는다. 셀 간 높이 모순·미결정·0/음수 행은 계속 거절한다.
  새 셀 높이는 지정한 행 합, 새 표 높이는 지정한 전체 행 합이며 가로 값은 보존한다.
- `cell.setSize`: 너비/높이 중 **요청한 축만** 복원하고 수정한다.
  너비만 요청하면 세로 최소값·배치 높이는 보존한다. 직접 병합 셀 수정 거절은 유지한다.
  바뀌지 않는 셀 최소값에 기존 여백 초과 조건을 새로 강제하지 않는다.
- `cell.setFormat`의 여백 변경은 구조와 해당 셀 크기·새 유효 여백만 검사한다.
  무관한 표 전체 트랙 합 일치를 요구하지 않는다.
- `table.insert/deleteColumn`: 기존에도 가로 트랙만 복원했다.
  가로 절대 크기만 요구하고 세로 값은 그대로 복제/보존한다.
- `table.insert/deleteRow`: 기존에도 행 합과 배치 높이의 일치를 요구하지 않았다.
  세로 절대 크기만 요구하며, 기존 배치 높이에 복제 행의 저장 높이 최댓값을 가산하거나
  삭제 행별 최댓값 합을 차감하는 기존 계약을 유지한다. 양의 HWPUNIT 범위 검사는 유지한다.
  세로 병합 경계·템플릿·삭제 거절 조건도 유지한다.
- `hae-model`의 가용성 메타데이터도 명령별 상대 크기 축 판정으로 맞췄다.
  요청값에 따른 정밀 검증은 여전히 실행기의 책임이다.

`hae-verify`는 원본과 요청만으로 기대 바이트를 계산한다. 가로/세로 구간은 자체 BFS로
풀며, `hae-edit`의 순차 전파 풀이·편집 계획·intent를 소비하지 않는다.
`Cargo.toml`에 `hae-edit`·`hae-model` 의존성을 추가하지 않았다.
`table_structure.rs`도 독립적으로 수정 축의 상대 크기만 검사한다.
치수 intent의 미요청 `widths`/`heights`는 빈 배열이다(그 축을 복원하지 않았다는 뜻).
