# 보고서 객체 생성·삭제 확장 (2026-10-19)

상태: 네 명령의 구현, 독립 검증기, Linux 전체 관문을 완료했다. 실제 한컴 열기·저장·재열기는 미확인이다. 최종 설치·실행 증거는 이 계획과 구별해 별도 결과 기록에 남긴다.

요청은 유의사항 표 삭제, 캡션 앞 새 PNG 삽입, 기존 객체가 없는 문서의 새 네이티브 수식·결과표 생성이다. 지도교사 이름은 사용자 입력이며 생성하지 않는다. 실제 미적분 보고서는 다른 세션이 편집한다. 이 작업은 합성 문서로 엔진 기능을 확장한다.

## 계약

- `table.delete`: 선택한 표의 XML 부분 트리만 제거한다. 표를 담은 문단, 구역 속성, 형제 내용, 기존 미디어를 보존한다.
- `table.insert`: `target` 문단의 `before` 또는 `after`에 독립 문단과 직사각형 표를 만든다. `rows`, `columns`, `width`, `rowHeight`를 명시하고 `cells`는 빈 배열 또는 정확한 행×열 문자열 배열이다. 셀 수는 1024 이하이다.
- `image.insert`: 같은 문단 위치 규칙으로 새 그림을 만든다. 입력 `path`는 기존 루트 격리 정책으로 한 번 읽어 고정한다. 기존 미디어를 수정하지 않고 새 manifest 항목과 원본 이미지 바이트를 추가한다.
- `equation.insert`: 같은 위치 규칙으로 HWP 수식 스크립트를 담은 새 네이티브 개체를 만든다. Unicode 본문이나 LaTeX 변환으로 대체하지 않는다.
- 그림·수식의 `width`, `height`와 표 치수는 양수 HWPUNIT이며 각 값은 1,000,000 이하이다. 수식 상자 크기는 명시적 요청값이며 실제 글리프 측정값이라는 주장을 하지 않는다.
- 초기 삽입 대상은 구역 직속 문단이다. 구역 속성을 소유한 첫 문단 앞에는 삽입하지 않는다. 중첩 위치를 지원하지 않는 경우 이유를 명시한다.
- 새 객체가 원문에 없어도 동작해야 한다. 기존 스타일 참조를 사용하며 없는 스타일을 추측하지 않는다.
- `NodeRemap::Paragraphs`의 허용 범위를 넓히지 않는다. 새 객체 작업에만 명시적으로 제한된 ID 사상을 적용한다.
- 저장 전 `hae-verify`는 원본과 선언된 요청에서 기대 바이트·미디어·캐시 변경을 독립적으로 계산한다. 편집기의 직렬화 결과를 정답으로 사용하지 않는다.

## 기존 구현 참고

사용자가 MCP 이전 스킬과 스크립트 참고를 요청했다. 로컬 `~/.codex/skills/hwpx-workbench/SKILL.md`, `references/contracts.md`, `scripts/hwpx_workbench/build.py`와 `vendor/hwpx_utils.py`의 `equation_xml`, `picture_xml`, `table_xml`을 구조 참고 자료로 사용한다. 해당 워크벤치의 전체 XML 재직렬화 방식을 현재 부분 편집 경로에 도입하지 않는다. 구조 참고와 현재 엔진 검증 결과를 구별한다. 복제한 템플릿에 필요한 출처·MIT 고지는 보존한다.

## 파일 소유권

| DeepSeek 작업 | 소유 파일 |
|---|---|
| 수식 생성 | edit/verify의 새 `equation_insert.rs`, 전용 노트 |
| 표 생성 | edit/verify의 새 `table_insert.rs`, 전용 노트 |
| 그림 생성 | edit/verify의 새 `image_insert.rs`, verifier 이미지 구조 헬퍼 노출, 전용 노트 |
| 공통 통합 | model ID 사상, edit/verify 공통 객체 모듈·열거형, registry/session |
| 부모 통합·검증 | 실행기 회귀 시험, 시나리오 실행, 문서·배포 기록 |

각 구현은 `opencode` / `opencode-go/deepseek-v4.1-flash`로 위임한다. 검토는 새 작업 ID로 별도 위임한다. 공유 파일을 여러 작업이 동시에 편집하지 않는다.

## 완료 게이트

1. 새 문서에서 세 종류를 만들고 쿼리·후속 편집·저장·재열기한다.
2. 여섯 캡션 앞에 여섯 그림을 넣고 본문 순서와 미디어를 확인한다.
3. 표 삭제에서 구역 속성과 표 밖 내용을 보존한다.
4. dryRun 비변경, Undo 원본 바이트 일치, Redo 새 ID 유지, 프로젝트 재열기 ID 보존, 배치 경로 이동·실패 원자성을 확인한다.
5. 독립 검증기가 요청 밖 본문·미디어 변조를 거부한다.
6. 관련 시험·정적 검사·전체 `scripts/check.sh`와 실제 MCP 호출을 통과한다.
7. rhwp 출력과 Linux 한컴 생존은 각각 기록한다. Windows 한컴 열기/저장/재열기는 실제 증거가 없으면 `not_checked`로 남긴다.
8. 새 실행 파일을 버전 디렉터리에 설치하고 다른 세션용 명령 안내를 갱신한다.
