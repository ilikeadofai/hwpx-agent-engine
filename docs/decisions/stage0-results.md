## S2 rhwp 어댑터

### S2-a 렌더링과 줄 배치 캐시 — 통과, §11 개정

`rhwp export-svg <파일> -o <폴더> --json`은 페이지별 SVG와 JSON 매니페스트(pageCount, pages[].path, overflowCellLines, untrustedContent 등)를 내고, 배치 경고(LAYOUT_OVERFLOW, LAYOUT_TABLE_OVERLAP)를 stderr로 낸다.

보도자료 서식(1쪽 20번 문단)에서 대조한 결과(2026-10-16 재실행으로 다시 확인):

| 변형 | 내용 | 쪽수 | 새 경고 |
|---|---|---|---|
| 0 원본 | 손대지 않음 | 2 | 없음(원본에 이미 있는 겹침 2건·넘침 1건은 모든 변형에 공통) |
| C | 글은 그대로, 그 문단 캐시만 제거 | 2 | 없음. 원본과 같은 배치 |
| B | 글을 길게 바꾸고 옛 캐시 유지 | 2 | 경고는 없지만 옛 줄 정보로 그림 |
| A | 글을 길게 바꾸고 그 문단 캐시만 제거 | 2 | 20번 문단 마지막 줄이 1쪽 아래 여백을 9.5px 넘음 |
| E | 글을 길게 바꾸고 그 문단부터 구역 끝까지 캐시 제거 | 3 | 없음. 넘친 줄이 다음 쪽으로 감 |
| D | 글을 길게 바꾸고 구역 전체 캐시 제거 | 3 | 없음. E와 같은 쪽수 |

해석: rhwp는 캐시가 없는 문단을 스스로 줄 나눔하지만, 캐시가 남은 뒤 문단들의 위치 정보를 쪽 나눔에 그대로 쓴다. 그래서 수정 문단의 캐시만 지우면 쪽 나눔이 갱신되지 않는다. 수정 문단부터 구역 끝까지 지우면(E) 쪽 나눔까지 다시 계산한다. 앞 문단까지 지우는 D와 결과가 같으므로 앞 문단의 캐시는 남겨도 된다.

세 문서로 넓혀 다시 확인한 결과(spikes/work/s4_package, rhwp 렌더링):

| 문서 | 원본 | A(수정 문단만) | E(수정 문단부터 구역 끝까지) |
|---|---|---|---|
| 보도자료 (section0, 문단 8) | 2쪽 | 2쪽, 문단 마지막 줄이 1쪽 아래 여백을 9.5px 넘음 | 3쪽, 새 경고 없음 |
| 계획서 (section0, 문단 13) | 19쪽 | 19쪽, 아래 여백 23.3px 넘침 | 21쪽, 경고 없음 |
| 다중구역 (section17, 문단 0) | 28쪽 | 28쪽, 새 경고 없음 | 28쪽, 새 경고 없음 |

주의할 점: 캐시를 지운 문단은 rhwp가 자체 규칙으로 줄 나눔하므로 한컴과 다를 수 있다. 글을 고치지 않고 계획서의 13번 문단부터 캐시만 지워도 rhwp는 19쪽 문서를 20쪽으로 배치했다(전체를 지워도 20쪽). 보도자료도 글을 고치지 않고 8번 문단부터 캐시만 지우면 원본에 없던 표 넘침 경고(120.3px)가 하나 생겼다. 따라서 캐시를 지운 구역의 rhwp 쪽 번호는 한컴 쪽 번호가 아니라 추정값이다. 이는 §7의 source=renderer-estimated 표시와 맞으며, 한컴에서의 쪽수는 S4에서 따로 기록한다.

결정: 설계서 §11을 "수정한 최상위 문단부터 그 구역의 마지막 최상위 문단까지 캐시 제거"로 바꿨다. 한컴이 같은 문서를 받아들이는지는 S4 변형 E로 확인한다. 변형 이름은 위 표와 같다.

### S2-b rhwp 위치 정보와 nodeId 대응

판정: **0.1 범위에서 가능**. 조사·스크립트는 Sonnet 5.5(spikes/s2_mapping/map_paths.py, 상세 spikes/work/s2/nodeid_mapping.md), 총괄이 28구역 문서로 다시 실행해 건수를 확인했다.

- 주소 출처: `export-render-tree`(쪽별 개체와 표·그림의 pi/ci, 셀의 row/col)와 `dump-pages --json`(쪽별 구역 번호와 개체 종류)을 함께 써야 한다. render-tree에는 구역 번호가 없다.
- rhwp 문단 번호는 구역 XML의 최상위 `hp:p` 서수와 같다. 컨트롤 번호 ci는 secPr·colPr를 포함한 문단 안 컨트롤 순번이라 우리 쪽에서 같은 규칙으로 계산해야 한다.
- 구역 번호는 content.hpf spine 순서다. 파일 이름 순으로 맞추면 28구역 문서에서 187건이 어긋났다.
- 셀은 `hp:cellAddr`의 행·열로, 표 안 표는 바깥 셀을 거쳐 대응된다. 쪽에 걸친 표는 쪽마다 행 범위를 알 수 있다.

공개 서식 23개 파일 합계(같은 원본의 변형 포함):

| 종류 | 유일 대응 | 모호 | 주소 없음 |
|---|---|---|---|
| 최상위 문단 | 5810 | 0 | 0 |
| 표 | 187 | 0 | 0 |
| 셀 | 2814 | 0 | 0 |
| 그림 | 63 | 0 | 90 (그룹·글상자 안 87, 머리말 3) |

대응하지 못하는 경우: 그룹·글상자·머리말·꼬리말 안의 그림과 도형, 셀 안 수식은 rhwp 출력에 주소가 없다. 한 셀의 두 문단에 각각 그림이 있으면 키가 겹친다(합성 사례). 자기닫힘 `<hp:p/>`는 rhwp가 건너뛰어 뒤 문단 번호가 당겨진다(합성 사례).

결정: 0.1의 쪽 정보는 최상위 문단·표·셀·그림(최상위 문단 안 또는 셀 안에서 키가 유일한 것)만 제공하고 나머지는 unavailable로 둔다. 조인 전에 쪽 수, 표 행·열 수, 개체 종류, 텍스트 앞부분을 대조해 하나라도 어긋나면 그 구역의 쪽 정보 전체를 unavailable로 한다. 자기닫힘 최상위 문단이 있는 구역도 unavailable이다. 단계 3 계획에 반영한다.

한계: rhwp 소스 사본에 .git이 없어 소스와 후보 커밋의 일치는 파일별 내려받기 기록으로만 확인된다. 각주·다단·바탕쪽·양식 개체는 시험 문서에 없었다.

## S3 격리 실행 — 통과

spikes/s3_sandbox/run_sandboxed.sh: `bwrap --unshare-all --die-with-parent --new-session --clearenv`, /usr·/etc/fonts 읽기 전용, 입력 /in 읽기 전용, 출력 /out만 쓰기, 새 /tmp, 홈 없음.

- 틀 시험(spikes/work/s3): 네트워크·DNS 차단, 입력 읽기 전용, 홈 디렉터리 숨김, 출력 폴더만 쓰기 가능.
- rhwp 실행(spikes/work/s3run): E_from_edit.hwpx를 격리 안에서 SVG 3쪽으로 렌더링. 종료 코드 0, 격리 밖 실행 결과와 3쪽 모두 바이트 동일.
- 입력 영역(/in/evil)에 출력하게 하면 "Read-only file system"으로 종료 코드 1.
- /home/x에 출력하게 하면 종료 코드 0이지만, 격리 안의 버려지는 임시 루트에 써졌을 뿐 호스트의 /home/x는 생기지 않았다. 어댑터는 /out 안에서 매니페스트에 적힌 파일만 읽는다(§9에 반영).
- rhwp는 libc·libm·libgcc_s만 동적으로 연결한다. 배치는 rhwp 내장 글꼴 메트릭으로 하며, SVG에는 글꼴 이름만 들어간다. PNG 래스터화에 쓸 글꼴 마운트는 단계 3에서 정한다.
- 해시: rhwp 4810a4a6ff2f…, E_from_edit.hwpx 3d01965c0d8d… (spikes/work/s3run/SHA256SUMS.txt)

## S4 한컴 재열기 — 사용자 확인 대기

시험 묶음: spikes/work/S4_한컴재열기_시험묶음.zip. 문서 3종마다 원본(0), 수정 문단 캐시만 제거(A), 옛 캐시 유지(B), 수정 문단부터 구역 끝까지 캐시 제거(E)를 넣었다.

변형 E는 spikes/s4_variant/strip_lineseg_tail.py로 A 파일에서 만들었다. 이 스크립트는 DeepSeek V4.1 Flash가 T3의 OpenCode 경로로 작성했고, 총괄이 코드를 읽고 실행해 확인했다(provenance.json). 세 파일 모두 바뀐 ZIP 항목은 해당 구역 XML 하나뿐이다. 그 XML은 A에서 캐시 요소 범위만 정확히 뺀 바이트와 같고, 항목 순서·압축 방식·mimetype 위치가 유지되며 ZIP 검사도 통과했다. 지운 캐시 수는 보도자료 28개, 계획서 180개, 다중구역 26개다.

묶음은 문서 3종 × 4개 HWPX, 점검표, 결과 양식, SHA256SUMS.txt로 15개 파일이다. 묶음 해시는 8cb5917e2c95…다. 점검표에는 E를 가장 중요한 확인 대상으로 적었다.

S4 결과에 따른 처리:

- A·E 모두 정상: §11 규칙(E 방식) 확정.
- E만 정상: §11 규칙 확정.
- E도 비정상: 줄 배치를 직접 계산해야 할 수 있다. 조판 엔진 범위이므로 0.1 범위를 다시 논의한다(§14).
