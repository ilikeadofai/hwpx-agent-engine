# 한컴 한글 SDK 분석 안내 (선택 작업)

이 문서는 일반 한글 데스크톱 확인(`00_시작하기.md`)을 마친 뒤, 별도의 **한컴 한글 SDK**를 분석할 때 지키는 절차와 원칙을 정리한 안내서입니다.
분석 대상은 공식 사이트(https://sdk.hancom.com/)에서 제공하는 별도 한글 SDK이며, PC에 설치된 한글 프로그램의 자동화 기능(HwpObject Automation API)과는 다른 제품입니다.

---

## 0단계 (선행 필수): 약관 확인과 분석 범위 제한

- [ ] **다운로드 시점의 약관부터 확인합니다.**
  - SDK 평가 패키지나 문서를 내려받을 때 제공되는 라이선스·이용 약관에서 **역공학(리버스 엔지니어링), 디컴파일, 동적 추적 금지 여부**를 가장 먼저 확인하고 기록합니다.
  - **만약 약관에서 금지되어 있거나 허용 여부가 불명확하면, 분석은 '공개 API 입출력 비교'로만 한정합니다.** (이 경우 아래 6단계의 로컬 동적 추적은 수행하지 않고 생략합니다.)

---

## 핵심 준수 원칙 (클린룸 및 보안)

1. **클린룸(Clean-room) 원칙 유지**
   - 프로젝트의 클린룸 원칙(`docs/decisions/clean-room.md` 및 설계 문서 §12)에 따라, **비공개 SDK 내부 구현이나 디컴파일 결과를 엔진 구현 자료로 절대 넘기지 않습니다.**
   - 엔진 개발 쪽으로는 오직 **공개된 API 계약, 검토된 입출력 동작 명세, 직접 만든 자작 시험 문서**만 전달합니다.
   - 주의: 이 기술적 분리 절차 자체가 법률적 적합성 판정을 대신하는 것은 아닙니다.
2. **외부 유출 금지**
   - 발급받은 **API 키, 라이선스 파일, 독점 DLL 파일, SDK 설치 폴더 전체**를 공개 저장소(GitHub 등)나 외부 AI 모델에 절대 올리지 않습니다.
3. **추정 확정 금지**
   - 실제 SDK 패키지의 DLL과 약관을 직접 확인하기 전에는 **함수 이름, ABI, 지원 운영체제, 무인(headless) 실행 가능 여부, 렌더링 API 제공 여부를 추측해서 확정하지 않습니다.**

## 단계별 진행 순서

### 1단계: 패키지 기본 정보 기록
- [ ] 공식 사이트에서 평가용 패키지, 가이드 문서, 샘플 코드를 확보합니다.
- [ ] 패키지 버전, 아키텍처(x86/x64 등), 압축 파일의 SHA-256 해시값, 제공 약관 전문(보관용)을 기록합니다.

### 2단계: 공개 API 기능표 작성
- [ ] 공식 가이드 문서, 공개 헤더 파일, 샘플 코드만 보고 아래 기능의 지원 여부와 호출 방식을 표로 정리합니다.
  - 문서 열기 / 저장하기
  - 화면 렌더링 또는 PDF/이미지 변환
  - 본문·표·그림 편집
  - 오류 코드 및 예외 처리

### 3단계: 패키지 구성 목록 확인
- [ ] 포함된 파일 목록, 실행 파일/DLL의 PE 아키텍처, 파일 버전, 디지털 서명 여부, SHA-256 해시, 공개된 export 목록 또는 타입 정보를 기록합니다.

### 4단계: 공식 샘플 그대로 실행하기
- [ ] 제공된 공식 샘플을 코드를 고치지 않은 상태로 실행해 기준 출력물을 확보합니다.

### 5단계: 자작 문서로 한 가지씩 입출력 비교하기
- [ ] 직접 만든 시험용 문서(`user_fixtures`)에 **한 번에 한 가지 작업씩만** 수행합니다.
- [ ] 작업 전후의 HWPX 내부 XML, 출력 PDF, 반환된 오류 코드를 비교합니다.
- [ ] **우선 확인할 질문 5가지**:
  1. 줄 배치 캐시 삭제 뒤 다시 조판(재조판)하는 시점과 조건은 무엇인가?
  2. 문단 서식을 복제할 때 어떤 속성이 유지되는가?
  3. 표의 셀 내용이나 그림을 교체할 때 어떤 XML 요소가 함께 바뀌는가?
  4. 쪽 번호나 요소 좌표를 조회하는 공개 API가 있는가?
  5. 문서를 저장할 때 SDK가 자동으로 정규화(정리)하는 범위는 어디까지인가?

### 6단계: 로컬 관찰 환경 추적 (약관이 허용할 때만)
- [ ] **0단계 약관 확인에서 금지되지 않았고 명확히 허용되는 경우에만** 수행합니다.
- [ ] 공개 API 문서만으로 설명되지 않는 차이가 있을 때, 로컬 관찰 환경에서 파일 접근이나 모듈 로드, 호출 전후 상태를 확인해 원인을 좁힙니다.

### 7단계: 명세 정리 및 인계
- [ ] 관찰한 결과를 **입력 / 조건 / 출력 / 기대 규칙** 형태로만 깔끔하게 정리합니다.
- [ ] 정리한 규칙을 바탕으로 독립 엔진 쪽에서 회귀 시험(테스트)을 작성해 구현합니다.
